## The R4.5 post-mission arc (the headline)

The campaign-sim crash on mission-return spanned S35–S44. The diagnosis inverted several times —
each turn logged honestly per the validation methodology:

1. **S41** — measured the corrupt SAGs against healthy ones: byte-identical in every safe field
   (`size`/`deaded`/`movecode`), only `type` differs ⇒ **no safe predicate** to skip them; the S40
   "skip the SAG in `MoveAllSAGs`" direction is dead.
2. **S42** — `BOB_CAMPFLY_NOFLY` probe showed the fresh SAGs aren't band-ticked pre-takeoff ⇒ the
   corruption is the **post-mission rebuild**, not creation.
3. **S43** — `FixupAircraft` trace: the SAG `type` is a **squadnum**; the corrupt value (160) is an
   out-of-range squadnum whose `Node_Data[160]` is invalid. Landed the systemic fix:
   `NodeData::operator[]` (the funnel every squadnum→Squadron lookup passes through) honors its own
   `assert(sq<SQ_MAX)` and returns a neutral squadron for an out-of-range squadnum (the S37
   `ConvertPtrUID` move). Clamp count `17→0`.
4. **S43c** — a compile-time reveal (`PT_BADMAX=18`, `SQ_LW_START=75`, `SQ_MAX=148`) corrected the
   story: the "healthy" 210 is *also* out of range — it's the **whole intercepted raid package**, and
   S39's clamp hit only 160 by luck of the OOB-read value.
5. **S44 ★★ — the real fix.** A decode trace showed the out-of-range squadnums came **straight out of
   `DecodePackage`** (the base-90 encode/decode is symmetric, so valid data round-trips) ⇒ the *file*
   was wrong, not the decode. `SAVEGAME/Package.dat` is the **Apr-18 shipped template, never written by
   any run.** The live `Package.dat` write lives in `CMainToolbar::OnClickedFrag2` (MAINTBAR.CPP:681);
   the campaign-mission **`BOB_CAMPFLY_GO` scaffold** launches `bobfrag` directly (the mission-folder
   OCX isn't built), **bypassing that save** — so post-mission reloaded stale data → the crash. **Fix
   (`FULLPSYS.CPP`):** the scaffold now writes the live `Package.dat` before flying, mirroring
   `OnClickedFrag2`. **Verified on `:0`:** post-fly decode squadnums valid (112/113/126/76, all <148);
   **0 clamps, 0 SEGV** — the post-mission sim advances past the entire crash family
   (`GetCruiseAt` + `SAGDecisionPreCombat`). The S43 `operator[]` guard stays as defense-in-depth.

## Open: S45 — diagnosed + designed, NOT implemented (blocked on shell)

With the S44 crash gone, the post-mission flow now **advances to a 640-res debrief dialog (`dial640`)**
that loads `artwork/DIAL640/title.bmp` — a **genuinely-missing asset** in this (partial) install. The
loader infinite-loops on it:

- **Root cause:** `fileman::opennumberedfile()` (FILEMAN.CPP:990–1039) `while(!retval){…}`. On Linux a
  missing numbered file calls `ReallyEmitSysErr` (non-halting in compat) then retries forever — Windows
  shows a Retry/Cancel "insert CD" dialog; headless Linux has no CD ⇒ spins (floods stderr; a plain
  front-end boot hits it 0×, so it's post-mission-specific = proof the flow advanced there).
- **Fix (two coordinated `#if BOB_LINUX` changes):**
  1. `opennumberedfile`: return NULL for a genuinely-missing file (break the loop).
  2. `makefileblock` (FILEMAN.CPP:~1243–1314): guard the NULL filehandle **before** `getfilesize()`
     (which does `ftell(NULL)` → crash) and skip the alloc+`readfileblock`; leave the block empty so
     `getdata()` returns NULL and `RDialog::DoPaint` (RDIALOG.CPP:1331, already `if(pData && pData[0]=='B')`)
     skips the missing background → graceful degradation, no loop.
  - **Caveat to verify on build:** dir-file callers (`makedirectoryname`/`filesindir`/`namenumberedfile`)
    deref `getdata()` without NULL checks, so a missing `DIR.DIR` would then crash instead of loop
    (acceptable — broken install — but confirm leaf-artwork misses don't route through them).
- **Why not implemented:** the harness **Bash tool went down for the agent** mid-S45 (every command,
  even `true`, returns exit 1 — the user's interactive `!` shell still works, so it's the agent's Bash
  execution path specifically). The fix touches the **core file loader** and the project DoD requires
  every change to build clean + be verified with evidence — which the agent cannot do while Bash is down.
  Full design is in scrum task #8 and above. **Verify after implementing:** rebuild; run the S44
  campaign post-mission repro — the `title.bmp` error should appear once (not flood) and the debrief
  should render without the missing background; bare `./bob` exits 0.
