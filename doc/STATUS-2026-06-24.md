Quick Mission → 3D flight → debrief → menu, with audio + keyboard/joystick/mouse). This session

### S24–S26 — R4.3: the campaign mission loop
With the campaign sim running (R4.5), drove the campaign's own **map→mission seam** without the
heavy CRToolBar/mission-folder OCX subsystem. Key finding: a fresh campaign day holds only the
**AI opponent's** packages, so flying requires *creating* a player package — the scaffold performs
the game's own **interception** (`HostilesList::OnClickedRbuttonauthorise` equivalent:
`Todays_Packages_NewPackage(live-raid-squadron, RAF intercept profile)`), then
`LaunchFullPane(&bobfrag, UIR_FRAG)`. The briefing's **Fly** item navigates to the *same*
`quickmissionflight`/`StartFlying` screen Quick Mission uses, so the campaign flight **reuses the
proven R1.1b Launch3d bridge** (one fix: set `MMC.playersquadron` at Fly time — a just-scrambled
interceptor is outside the briefing's flyable-status gate). The mission end (`BOB_AUTOQUIT=debrief`
→ EXITKEY → `OnFlyingClosed(IDOK)`) routes by `gamestate` (COMMANDER) to the campaign branch
(`NextMission` + `StartUpMapWorld` + `LaunchMap`) → back to the strategic map. One deferral
(precisely characterized): fast-forwarding the *post-mission* sim hits the R4.5
`ConvertPtrUID`-NULL SAG-AI family; guarded off (the returned map is paused in real play).

### S27 — R4.2: strategic-map icons (spike, banked)
The dynamic-icon path is wired + reached (`UpdateBitmaps → DrawIcons → DrawIconTest → MaskIcon`
on R6.1's blit) but `DrawIcons` receives an **empty `inter` clip rect (0,0,0,0)** → the world-rect
cull rejects every item (`raw_p` large = items exist, `survived_cull=0`). The terrain renders
because per-block `StretchDIBits` uses the block rect directly, not `inter`. Root: the icons are
positioned by the **`CMapDlg` scroll/world transform** the headless `UpdateBitmaps` shim never sets
up → R4.2 icons is a **coordinate-system subsystem** (drive the real `CMapDlg` paint, or adopt MA's
further-along map view). No code shipped (trace added → measured → reverted; game code pristine).

### S28–S32 — R4.4: save/load, end to end
Save/load went from "no save ever lands on disk" to **fully click-driven**:
- **S28 (save persists):** `CFiling::SaveGame` wrote via the corrupted `fakefile` savegame path —
  the *same* stateful-global bug `CFiling::LoadGame` was already `#if BOB_LINUX`-bypassed for, but
  `SaveGame` (its twin) never was. Fixed → `SAVEGAME/Auto Save.BSR` (225 KB real `Miss_Man`).
- **S29 (load restores state):** the Sprint-28-retro "general `ConvertPtrUID` sentinel" hypothesis
  was **disproven** (its `info_*Ptr` conversions are pure address casts — already NULL-safe). ASan
  pinned the real crash to a **heap-buffer-overflow at `MIGView.cpp:2210`** — the `raidnumentries`
  terminator loop overrunning because *deserialised* packages lack the terminator `RecostRaidList`
  sets at runtime (R4.5 terminator family). Fixed: re-run `RecostRaidList()` on loaded packages in
  `PackageList::LoadGame` (`MAPCODE.CPP`) + `if(ac)`-guard the unguarded `ac->SetDraw()` sites.
  ASan-verified gone. Round-trip proven: `LoadGame -> OK, currtime 26660 → 32180` (loaded = saved).
- **S30 (load screen lists saves):** `CLoad::MakeFileList`'s `_findfirst` search path used the
  *same* `fakefile` bug — the **3rd twin** (Save / Load / CLoad-enumeration). Fixed → the screen
  shows "Auto Save".
- **S31 (load → campaign map):** the "Load" menu item is `DoLoadGame` = `LoadGame` + `LaunchMap`
  (NOT the R4.2-blocked `CFiling::OnOK` CMainFrame path) → loading enters the strategic map on the
  restored state.
- **S32 (file-row click — R4.4 DONE):** the OCX Select eventsink is a no-op on Linux → a targeted
  `BOB_LINUX` bridge (mirrors the R5.3b SController bridge): `CLoad::bob_file_clicked` →protected
  `OnSelectRlistboxfile`, a `g_bobCLoad` registry, `OleHost::rowAtY` → `HostRListBox::GetRowFromY`,
  routed by `bob_ole_click`. Verified by **genuine clicks**: click "Auto Save" → `selectedfile` set
  → click "Load" → `LoadGame=1 → LaunchMap → strategic map active`.

## Next-session plan — S33 spike: adopt MA's general eventsink (scoped, ready to implement)

The cross-port threshold is met (BoB has **two** targeted OCX-eventsink bridges now: R5.3b controls +
S32 CLoad). Spiked adopting MA's general `ma_eventsink.cpp` — it is **bounded and compile-safe**:

- **Mechanism (MA, verified):** `BEGIN_EVENTSINK_MAP` emits a file-scope auto-registrar struct whose
  ctor calls `theClass::MaRegEvents()` at **static-init** (no per-dialog hook needed); `ON_EVENT`
  registers `{&typeid(theClass), id, dispid} -> thunk`, the thunk calls `evt_call(dlg, &Class::fn)`.
  `evt_fire(parent, &typeid(*dlg), id, dispid)` (from the click router) matches by RTTI + id + dispid
  and calls the handler. An `evt_call(C*, M){}` **fallback template** means any uncovered handler
  signature still compiles (just doesn't fire) — so the 83 `BEGIN_EVENTSINK_MAP` TUs are compile-safe.
- **Prereqs confirmed:** RTTI is ON (build default); `OnSelectRlistboxfile(long,long)` is already
  covered. The one delta the cross-port notes flagged: BoB's `OnTextChanged*(LPCTSTR, short)` needs
  **one extra `evt_call` overload** added (else those hit the no-op fallback).
- **Adoption steps (≈3 files):** (1) replace the no-op eventsink macros in `SRC/compat/afxwin.h` with
  MA's macros + the `bob_evt_call` templates (+ the `(LPCTSTR,short)` overload) + extern decls;
  (2) add `SRC/compat/bob_eventsink.cpp` (port `ma_eventsink.cpp`: register/fire + `evtA0/A1/P`) and
  add it to `SRC/compat/CMakeLists.txt`; (3) call `bob_evt_fire` from `bob_ole_click` (set
  `bob_evtA0/A1` = row/col before firing for list Select), then **retire** the two targeted bridges
  (`bob_scontroller_combo_changed`, `bob_cload_file_clicked`). Validate with a **full rebuild** (the
  83 TUs now take handler addresses — the no-op macros masked any stale `ON_EVENT` refs, so expect to
  fix a few) + re-verify the CLoad file-row click and the SController rebind fire via the general path.
- **Alternative next picks if eventsink is deferred:** R4.2 map icons (drive the real `CMapDlg`
